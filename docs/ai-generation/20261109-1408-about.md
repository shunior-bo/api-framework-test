## Where CONVENTIONS.md was insufficient

- The spec documents no response body for `GET /about` (`content: {}`), so `AboutSchema` mirrors the observed GAD body, following the `HealthSchema` precedent. CONVENTIONS.md does not say how strict a schema should be when the contract has no body schema.
- `/about` has the OpenAPI tag `healthcheck`, the same as `/health`. `HealthClient` documents that it owns only `/api/health`, so the agent created a separate `AboutClient` and `about.spec.ts` (resource = path) instead of extending `HealthClient`. CONVENTIONS.md does not say whether the "resource" is the path or the OpenAPI tag. A rule would make this choice deterministic.
- The §3 client method vocabulary does not cover a singleton GET with no id. `get()` was used, as in `HealthClient`.
